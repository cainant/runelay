The desktop app ships the same runelay server and panel as the Docker image, packaged for macOS, Windows and Linux. It can run that server on your computer, or connect to a runelay server you host somewhere else.

## Install

| Platform | Download | Format |
|---|---|---|
| macOS, Apple silicon | [runelay.com/download/mac](https://runelay.com/download/mac) | `.dmg` |
| macOS, Intel | [runelay.com/download/mac-intel](https://runelay.com/download/mac-intel) | `.dmg` |
| Windows, x64 | [runelay.com/download/windows](https://runelay.com/download/windows) | `.exe` installer |
| Linux, x64 | [runelay.com/download/linux](https://runelay.com/download/linux) | AppImage |
| Linux, arm64 | [runelay.com/download/linux-arm](https://runelay.com/download/linux-arm) | AppImage |

Each link points to the file in the latest [GitHub release](https://github.com/runelay/runelay/releases/latest).

- **macOS**: open the `.dmg` and drag runelay to Applications.
- **Windows**: run the installer. It installs for your user only, with no options to pick.
- **Linux**: make the AppImage executable (`chmod +x runelay-linux-*.AppImage`) and run it.

The builds are not signed by a registered publisher, so macOS and Windows may warn the first time you open the app.

## First open

The app asks where runelay runs:

- **This computer**: the app starts its own server and opens the panel on the sign-up screen for the first account. No setup token to copy.
- **A server you already have**: enter its address. The app checks that the URL answers as runelay before saving it. Use `https`; plain `http` is only accepted for `localhost`, `127.0.0.1` and `.ts.net` addresses.

You can keep several servers and switch between them from **Settings → Server** in the panel or from the server list in the app menu. Switching restarts the app on the chosen server. If a remote server does not answer, the app offers to try again, switch back to this computer, or quit.

**Settings → Server → Open when the computer starts** works with a remote server too. The server is already running elsewhere, so this is only about the app: it opens hidden in the tray (the menu bar on macOS) when you sign in, and closing the window keeps it there. With the option off, closing the window behaves as before.

On macOS, **Mostrar no Dock** in the menu bar icon's menu takes the app out of the Dock and the app switcher (Cmd+Tab) when you turn it off. runelay keeps running in the menu bar, and its window still opens from the icon. The choice is kept across updates. It only applies while the menu bar icon is there, so the app never ends up with no way to open it.

## Setup in two clicks

In the desktop app, **Access → Set up agents** has two buttons instead of the step-by-step guide. You never open a terminal.

1. **Connect my agents** ("Conectar meus agentes"). The app finds the agents installed on this computer (Claude Code, Codex, Cursor, Grok and the ones whose memory runelay manages, like Gemini, Hermes Agent and OpenClaw) and shows each one with a live check. Behind the scenes it runs the bundled [CLI](/cli) for you: [`migrate`](/migrate) brings in MCP servers, memories and skills, [`connect`](/connect-agents) registers runelay in every agent and turns native memory off, [`pull`](/cli#pull) writes the short brief into `CLAUDE.md`, `AGENTS.md` and `GEMINI.md`, and [`doctor`](/cli#doctor) checks the result. With the server on this computer, it also turns on **Open when the computer starts**, since agents only reach runelay while the app runs.
2. **Connect my accounts** ("Conectar minhas contas") opens the catalog, where you sign in to Linear, GitHub, Notion and the rest once.

The first click creates an API key named `runelay desktop` with your signed-in session and keeps it in the app's `config.json`, one per server. You never see or paste it. The same key powers [skill sync](#skill-sync).

When something needs you, the row says so in plain words with one button: **Try again**, **Open file** for an instructions file that still tells an agent to save memory outside runelay, or **Sign in to accounts** for logins the import could not bring. On macOS, the import may ask permission to read the MCP logins Codex and Claude Code keep in the Keychain.

Using an app runelay doesn't know? Under the checklist, **My agent isn't listed** ("Meu agente não aparece aqui") opens a short panel, and it is the main message when no known agent is found. Any app that accepts an MCP server works: copy the server URL (`<server>/v1/mcp`), name the agent and click **Generate key** to get an `Authorization: Bearer rnl_…` header with its own key, shown once and revocable in **API keys** without touching the desktop's key. A ready-to-paste `mcpServers` JSON block covers most clients, and **See guides per agent** opens the [guides](https://runelay.com/guides/).

In a browser, the panel keeps the six-step guide.

## Updates

The app checks for a new release when it opens and every six hours after that. When there is one, it offers to download the installer for your system into your Downloads folder and open it; on macOS, drag the new app to Applications. You can also skip a version, or check by hand with **Check for updates** ("Buscar atualizações…") in the app menu or the tray menu. This works the same when the app is pointed at a remote server, where the panel only knows the server's version. Your data stays.

The app does not replace itself silently: you still confirm the installer. With the server on this computer, the panel also shows an update button in the rail with the release notes and a **Download** button.

## Skill sync

The app watches your agents' skill folders (the same ones [`runelay push`](/cli#push) reads). When you change a skill, it pushes that skill to the server, so every agent gets the new version without a manual `push`. It uses the key from [Connect my agents](#setup-in-two-clicks), or the one from `runelay login` when it points at the same server.

Turn it on or off with **Sincronizar skills** in the tray menu (the menu bar on macOS).

## Desktop app or server

On **this computer** mode, the app runs the same server binary as the Docker image, with a few differences:

| | Desktop app | Server (Docker) |
|---|---|---|
| Address | `http://127.0.0.1:4312`, fixed | Any `PUBLIC_URL`, port set by `RUNELAY_PORT` |
| Reachable from | This computer only | Anywhere you expose it, behind HTTPS |
| `RUNELAY_SECRET` | Generated on first open, kept in the system keychain when one is available | Generated by the installer into `.env` |
| Local MCP servers (`command`) | On. Commands like `npx` use the tools installed on your computer | Off by default (`RUNELAY_ENABLE_STDIO`), and the image has no Node |
| Updates | The app offers the new installer | One-click from the panel with the `updater` service, or `docker compose pull` |
| Runs while | The app is open | Always |

Because the app listens on `127.0.0.1:4312`, the [CLI](/cli) and your agents on the same computer find it without any configuration. Agents on other machines cannot reach it: for a team or several computers, [self-host a server](/self-hosting) and point the app at it.

Only one runelay can hold port 4312. If a Docker install is already running there, the app asks you to stop it first. See [Troubleshooting](/troubleshooting#port-4312-is-already-in-use).

## Where data lives

| Platform | Folder |
|---|---|
| macOS | `~/Library/Application Support/runelay` |
| Windows | `%APPDATA%\runelay` |
| Linux | `~/.config/runelay` |

The folder holds the SQLite database (`data/`), the server log (`server.log`), the app's server list (`config.json`) and the sealed secret (`secrets.bin`). When the system has no keychain, the secret is stored in `secrets.json`, readable only by your user. Back up the folder to keep your data.
